# Agent Configurations

This document describes the exact mechanics of each agent configuration implemented in
`src/protocols/`. All configurations share the same budget vector (T=200K tokens,
W=600s wall clock, K=25 evaluator calls) and the same task prompt. The
selection rule is: the artifact with the highest dev score among all artifacts
produced by a configuration is submitted for hidden evaluation.

---

## Single-Shot

One LLM call with the problem prompt. No iteration, no feedback.
Source: `src/protocols/baselines.ts → runSingleShot`.

---

## Best-of-N

Eight independent LLM calls, each with the same problem prompt but at
increasing temperature (0.60, 0.65, ..., 0.95). Temperature variation
introduces sample diversity without changing the prompt. All eight artifacts
are scored by the dev evaluator; the highest-scoring one is submitted.
Source: `src/protocols/baselines.ts → runBestOfN`.

This is the primary MEG denominator. Multi-agent configurations must beat this
to demonstrate that their collaboration mechanism, not repeated sampling,
is responsible for any performance gain.

---

## Self-Refine

One initial generation followed by three refinement rounds. Each refinement
call receives the current best solution and its dev score, and is asked to
improve it. The model retains the higher-scoring solution after each round.
Implements Madaan et al. (2023) directly.
Source: `src/protocols/baselines.ts → runSelfRefine`.

---

## VGS (Verifier-Guided Search)

A FunSearch-style evolutionary loop over solution artifacts. An initial
population of four candidates is generated via independent LLM calls at
slightly varying temperatures (0.80–1.10). Each candidate is scored by the
dev evaluator. Over five generations, the top two candidates (elites) are
retained and two new candidates are generated by a mutation call that
receives the current top-three solutions and their scores. The population
is merged after each generation and the top four are kept. The loop
terminates early if no improvement is seen for two consecutive generations.
Total evaluator calls: up to 20, within the K=25 cap.
Source: `src/protocols/vgs.ts → runVGS`.

---

## Homo-Chain

A sequential chain of four agents using the same backbone. Agent 1 generates
an initial solution. Each subsequent agent receives the current best solution
and its dev score, and attempts to improve it. The chain keeps the best
solution seen at each step.
Source: `src/protocols/multi-agent.ts → runHomoChain`.

---

## Cross-Chain

Same structure as Homo-Chain but with three different model families in
sequence (Claude → GPT-4o → Gemini). Each agent refines the solution
produced by the previous agent.
Source: `src/protocols/multi-agent.ts → runCrossChain`.

---

## MAgICoRe

Three-role pipeline: Solver generates an initial solution, Reviewer critiques
it without producing a new solution, Refiner improves the solution using the
critique. Two rounds of review and refinement run within the budget.
In the homogeneous variant all three roles use the same backbone. In the
diverse variant, Solver is Claude, Reviewer is GPT-4o, and Refiner is Gemini.
Implements the MAgICoRe architecture (Zhang et al. 2024).
Source: `src/protocols/multi-agent.ts → runMAgICoRe`.

---

## Debate

Two debaters (A and B) each generate an initial solution independently, using
different temperature and system prompts that emphasize different strategies
(temperature 0.9 for A, 0.5 for B). Over two rounds, each debater critiques
the other's current position. A synthesizer then receives both positions and
their dev scores and produces a final solution.
In the homogeneous variant all roles use the same backbone. In the diverse
variant, debater A is Claude, debater B is GPT-4o, and the synthesizer is
Gemini.
Source: `src/protocols/multi-agent.ts → runDebate`.

---

## MoA (Mixture-of-Agents, with Synthesis)

Three proposing agents generate solutions independently in parallel; they do
not see each other's outputs during generation. An aggregator then receives
all three proposals together with their dev scores and produces a synthesized
final solution. The aggregator uses Claude by default in all variants.
In the diverse variant, the three proposers are Claude, GPT-4o, and Gemini.
In the same-model variant, all three proposers are Claude.
Implements the MoA architecture (Wang et al. 2024).
Source: `src/protocols/multi-agent.ts → runMoA`.

Note: the aggregator prompt includes the dev score of each proposal. This
means the aggregator has access to relative quality information when deciding
how to combine proposals.

---

## MoA-NoSynth (Mixture-of-Agents, no Synthesis)

Identical to MoA up to and including the independent proposal phase. The
aggregation step is omitted entirely. The best proposal by dev score is
selected downstream. This is the ablation that isolates the effect of the
synthesis step from the effect of backbone diversity.
Source: `src/protocols/multi-agent.ts → runMoANoSynth`.

---

## HPE (Hierarchical Planning and Execution)

Described in `src/protocols/hpe.ts`. A planner decomposes the problem into
subgoals, executor agents tackle each subgoal, and a final aggregation step
combines the results.

---

## Retry Behavior

All configurations share a common retry mechanism for parse failures and verifier
rejections. If the LLM produces malformed JSON or a solution the verifier
rejects (e.g., wrong array length), the verifier error message is appended to
the next call so the model can self-correct. Generation steps allow up to 5
retries; intermediate refinement steps allow up to 2 retries to conserve the
shared budget. A cell that exhausts all retries at the first generation step
produces no artifacts and is excluded from aggregate MEG computation.

---

## Budget Enforcement

Every LLM call and every evaluator call is routed through a shared
`BudgetEnforcer` instance. The enforcer tracks cumulative token usage, wall
clock time, and evaluator call count. Any call that would exceed a cap is
silently dropped and returns null; the configuration handles null returns by
terminating early. This ensures all configurations operate under identical resource
constraints regardless of how many agents they employ.
Source: `src/budget/budget-vector.ts`.
